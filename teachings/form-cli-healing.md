# Repair by witnessed replacement

Source: Codex's 2026-09-07 repair movement, retained in
`receipts/2026-09-07-declarative-attention-and-source-repair.md` and its
verification JSON. These are observations with a date, not universal rules.

Start with the failing command, its process status, its expected result, and
the exact current source. Freshness returned 31 after bootstrap. A green number
beside a failed process was a refused candidate. A timeout was an incomplete
observation. Source balance, successful execution, and semantic truth are three
separate questions.

Read the filesystem and import chain. An unresolved name can mean a missing
prelude, a typo, a retired interface, or a primitive on another kernel. Search
definitions and callers; inspect git history to learn the intended contract.
Probe a lane before naming it. The missing tokenizer interface could not be
repaired honestly with an invented stub.

Try the smallest structural candidate in a snapshot. A missing closer often
belongs before the next definition or within a let/if/and expression, not at
EOF. Count comments and escaped strings correctly. Reject a candidate that
compiles but changes the expected band. Two IR functions sharing one name needed
distinct names and a regression exercising the accessor's actual meaning.

Keep expected values and historical observations out of a proposed source
repair. An Arabic replay differed on one candidate after the corpus changed;
the old recording remained intact. Missing Java and Kotlin were unavailable
resources. Neither case became green through changing the expected result.

Collect RAG hits with their source references, then read the current source.
Old examples, git patches, model answers, and adapters are evidence to inspect.
They do not grant execution authority. Preserve failed attempts alongside the
eventual repair so retrieval does not mistake an attractive failed candidate for
a successful one.

Let real progress guide execution time. The dynamic Form supervisor observes
stage and token movement, adapts its next observation, and offers inspection
when output grows quiet. Process liveness alone does not establish semantic
progress. Explicit cancellation must preserve both the chosen action and the
observed process-group release. A failed signal is an OS observation, not a
reason to discard a completed trainer's exit record.

Use deterministic Form edits first, then an evaluated compatible adapter and
each eligible native model, then local models serving diagnosis, patching, and
review. Read roles, artifact presence, tokenizer index, seal, and the session
lane before building the native queue. The 2026-09-07 resource observation found
Q4 ready but omitted by the original single-answer-model choice. Registry
membership alone does not make an unwired model eligible.

Preserve each model's admission, candidate check or refusal, and completion as
separate observations. Starting one native model cannot satisfy another model's
owed attempt. A malformed inventory leaves an evidence gap and keeps remote
fallback closed. Every eligible native route either attempts or reports a concrete
inability before one remote CLI fallback. The remote answer is another local candidate;
the same checks apply. Provider absence and budget exhaustion are observations,
not successful repairs.

Accept only a changed production source with a fresh successful band, exact
expected stdout, empty diagnostic stderr, unchanged dependencies and tests, and
unchanged live input since the snapshot. Keep the original bytes and candidate.
Commit with a guarded replacement. Rejected candidates never enter the live
source. Tests in the snapshot remain executable programs, not an OS sandbox.

Store verified before/after examples and their checker contract in local repair
memory. Replay them as proposals and verify them again. They are training
candidates, not trained weights. Promote an adapter only with a compatible base
identity, artifact hash, held-out repair evidence, and a regression comparison.
The existing corpus-shaped seed proves buffer admission, not repair learning.

When the local learner is enabled, follow each non-evaluation candidate/check
round with an actual optimizer step on its observed outcome. Resume the last
candidate, retain both hashes and the changed tensor names, and verify that
base weights did not change. The 2026-09-07 recovery run trained 53 tokens and
changed 112 tensors with a verified process exit and released group. Both
validation losses printed as 1.295; rounding cannot establish zero regression.
That candidate update proves learning ran, while serving promotion still owes
independent repair evidence. An adapter file left by an interrupted supervisor
does not supply the missing process completion; rerun and observe a fresh one.

Measure with `heal eval` before treating saved examples as transferable skill.
Keep development, held-out, and correct-control observations separate. A
correct control remains unchanged; an already-passing repair case is an
invalid measurement. Count unresolved semantic defects instead of making the
expected result easier. Include boundary inputs that distinguish plausible
but incorrect fixes, such as positive fractions beside zero.
Require semantic cases to compile and execute cleanly before generation. A
missing checker prelude exposed this gap in the first evaluation attempt;
the strengthened baseline check now refuses that experiment before model cost.

Mark evaluation records at birth and exclude them from learning and replay.
The evaluator retains them under its own report directory, including failures
and the checker contract. It does not train weights or issue an adapter
promotion receipt. Native case evaluation isolates generation from retrieval;
the wider integration suite checks the resource routing that surrounds it.

Treat a timeout as a measured execution path. Retain process boundaries,
monotonic stage times, work counters, termination signals, and the policy's
offered, selected, and applied choices. Keep prompt and answer bytes out of
diagnostic events. Read `heal report|<evidence-directory>` before deciding
whether another attempt should change the budget, resource, or implementation.
Elapsed stage time includes waiting; it does not identify CPU or GPU utilization.

The 2026-09-07 Q4 trace located 264.921 seconds in prefill before a 300.016-second
timeout. Searching the named stage in current source found an existing batched
prefill path in `form/form-stdlib/form-cli-model-generate.fk` that session
admission had not inherited. A real four-position comparison returned equal
token/position results: 8,550 ms sequential and 587 ms batched. That observation
supported connecting admission to the existing path, with matching scratch
and slice widths from `form-cli-model-admission.bml`. It did not prove that the
model could repair a semantic defect; the full case needs its own result.

For a similar failure, search the observed stage and its callers, inspect
alternative callers and git history, and compare existing local implementations
under the same source and model contract. Verify outputs and resource release
before keeping a faster path. Save the next full run too: removing a prefill
bottleneck can expose decoding cost rather than complete the requested repair.
