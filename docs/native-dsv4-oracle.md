# Native DSV4 numerical reference

Form owns the independent GGUF reader, numerical recipes, retained vectors and
execution state used to check the DSV4 GPU programs. Its CPU matrix programs are
emitted and admitted in RAM on Darwin ARM64. The GPU programs are generated by
Form; Metal remains a dynamically admitted host carrier.

| Authority under `form/form-stdlib/bml/` | Responsibility |
| --- | --- |
| `dsv4-oracle-reference.bml`, `dsv4-oracle-tables.bml` | GGUF metadata and tensor extents, independent quantized reads, normalization, attention, hyperconnections, expert routing and complete layer recipes |
| `dsv4-oracle-native-matrices.bml`, `dsv4-oracle-resources.bml` | Ordered fp64 F16, MXFP4 and IQ2 reductions, MXFP8 owner selection, reusable output workspaces and explicit release |
| `dsv4-oracle-file-map.bml`, `dsv4-oracle-mapped.bml` | Read-only model mapping and complete borrowed weight spans |
| `dsv4-oracle-angle.bml`, `native-angle.bml` | RoPE phase selection and interval-based reduction of larger finite angles |
| `dsv4-oracle-stack.bml`, `dsv4-oracle-execution.bml` | Per-layer key/value history, state controls, complete numerical files, stdout metadata and ordered completion ledger |
| `dsv4-oracle-request.bml`, `dsv4-oracle-input.bml` | Complete physical input, finite typed configuration and admission before mapped weights and matrix resources |
| `dsv4-tensor-views.bml`, `dsv4-tensor-views-input.bml`, `dsv4-view-publication.bml` | Exact tensor view geometry and owned plan publication |
| `metal-fp32-compensated.bml` | Paired fp32 projection and normalization programs, with explicit arithmetic and dispatch contracts |
| `dsv4-proof-emission.bml`, `dsv4-proof-metadata.bml`, `dsv4-proof-output.bml` | Native shader and metadata emission, complete checked stdout and retained output settlement |
| `dsv4-proof-retention.bml` | Complete proof archive capture, exclusive publication and readback before caller cleanup |

The [ordered MXFP8 matrix owner](native-fp64-matrix.md) supplies the shared CPU
admission and workspace boundary. Independent scalar arithmetic remains
available for comparison. Selecting an arithmetic owner is explicit; an
unsupported format or invalid span refuses admission.

## Input and output

`observe/dsv4-oracle-run.bml` accepts one complete request on stdin. It accepts
twelve LF-separated fields with header `DFO1` and an optional final LF, twelve
NUL-terminated fields with header `DFO2` and an optional trailing LF, or a JSON
array of twelve strings behind an eight-byte little-endian byte length. The
JSON request uses header `DFO1` and permits no bytes after its exact payload.
The field order is:

| Field | Meaning |
| --- | --- |
| Header | Request framing identity |
| Model | Nonempty GGUF path |
| Token, position, count | Nonnegative exact integers; count is a layer index for a single layer and a positive layer count for a stack |
| Mode | `probe`, `hc`, `layer` or `stack` |
| Output | Output directory, or empty for stdout only |
| F32 state | `0` or `1` selects inter-layer state rounding; `env:<raw>` preserves inherited environment semantics, where only the exact raw value `1` enables rounding |
| Initial perturbation, per-layer perturbation | Finite numerical controls |
| Sequence | Ordered token IDs separated by ASCII whitespace, or empty for a single token |
| End | `END` |

Regular input is consumed from its current offset through the observed extent;
the owner verifies offset progression and file identity. Pipe input requires
complete framing and observed EOF. The input owner releases its generated
syscall code and owned mappings before numerical admission, retaining the
decoded Form request and preserving the borrowed input descriptor. Unsupported
socket and terminal descriptors refuse. Literal newlines in paths travel
through NUL or length framing. Invalid framing, types, nonfinite numbers,
overflow, vocabulary indices and model geometry refuse explicitly.

The reference carries a separate key/value history for each layer. A sequence
has exactly `position + 1` tokens and executes positions zero through that
position, with the final token supplying the checked output. A standalone token
uses the requested position. State rounding occurs before the per-layer
perturbation. These controls and sequence input apply only to stack mode;
other modes require zero rounding and perturbations with an empty sequence.
Output vectors retain all values with exact numerical
readback, including signed zero. The completion ledger advances only after the
layer's required files are written and read back. Expert metadata is complete;
the eight-value `ORA` display is a sample with a separate purpose.

## Residency and numerical boundaries

Matrix loops borrow the model's weight planes directly and reuse owned output
maps. Their products and reductions stay out of the bootstrap's boxed-float pool.
Small configuration vectors and decoded activations still enter Form lists.
Stage diagnostics currently obtain process RSS through an OS `ps` invocation.
These costs remain part of the observed reference; the complete computation is
not yet a graph of resident native activation spans.

File-map extent observations do not establish immutability against an external
writer or detect every same-size source replacement. The mapping and native
owners are cooperative process-local lifetimes. Their spans must remain valid
through each synchronous call and be released through their owners.

Each Metal view covers one complete tensor plus its necessary page alignment.
The Form plan derives that geometry from the tensor directory. The consumer
checks actual file extent, device extent, page alignment and complete tensor
containment. `observe/dsv4-tensor-views-run.bml` accepts six NUL-terminated
fields: `DTV1`, model path, device maximum, page size, output path and `END`.
The maximum and page size are positive exact integers supplied by the caller.
An exclusive new-file publication refuses an existing destination.
The publication library retains incomplete write state for an explicit retry
or abandonment. Abandonment attempts resource release and retains the partial
file for inspection; any unsettled resources remain owned for retry. The command
door refuses incomplete publication; it does not
offer resumable command execution or remove partial files automatically.

The generated F16 GPU matrix program carries product and addition residuals,
with implicit contraction and reassociation disabled. Key/value projection and
weighted RMS normalization select Form-generated paired fp32 programs. Projection
uses 32 lanes per row and retains residuals through the group reduction;
normalization retains its squared sum and reciprocal-square-root correction.
The attention and single-layer proof carriers select the same normalization
recipe without weights for their 16,384-value hyperconnection state.
The consumer verifies SIMD width, complete row groups, index extents and
normalization parameters before submission. The arithmetic contract covers
internally normalized finite pairs with normal-range intermediates. It does not
promise exact accumulation, universal correct rounding or underflow behavior.
The error-free transformation basis is described in
[Hida, Li and Bailey's arithmetic algorithms](https://www.davidhbailey.com/dhbpapers/qd.pdf);
the actual device comparisons below establish this program's observed behavior.

The [native proof emission door](native-dsv4-proof-emission.md) selects
`core-precision` or `hc-precision` and composes the complete shader in RAM from
its Form authorities. It owns complete framing, partial writes, interruption,
readiness and output settlement. Its metadata reader validates the complete
header and tensor extents before output, with no fixed header-size cap.

The reference attention
denominator accumulates the sink first, then key weights in order. Larger RoPE
phases use a derived pi/2 interval; the observed small-angle arithmetic remains
selected through magnitude eight. Independent finite-angle comparisons do not
establish universally correctly rounded trigonometry.

## Observed execution

The current full 43-layer GPU consumer passes all 861 checks at positions zero
and seven. The two-token, four-layer consumer passes all 184 checks, including
retained history, new key/value writes and untouched frontier sentinels. Both
use the original numerical thresholds. These executions compare actual GPU
results with the independent native reference over the same model and token
inputs.

The attention and complete single-layer callers separately pass all 30 and 31
checks, including their original relative-error criteria. The four consumers
pass 1,106 checks with 107 source and executable identities unchanged across
their executions. The Python reference is removed; all three callers use Form.
The [retained evidence](evidence/fkwu/dsv4-oracle.json) binds actual child
statuses, complete streams, ordered gates, reference vectors, resource
observations and proof archives. The sequence run generates all four native
references through the public caller; the full-stack run uses the separately
completed and rechecked 43-layer reference trajectories.

An isolated same-input comparison observes all 512 projection values and all
512 normalization values matching the independent fp64-to-fp32 results exactly.
All seven buffers and four pipelines in that comparison are physically released.
Those exact matches describe these captured inputs. They do not generalize the
arithmetic contract to every finite input.

The unweighted normalization comparison observes all 16,384 actual input values
producing the same fp32 outputs as the independent fp64 calculation. Its three
buffers and two pipelines are physically released. This isolates the numerical
leaf; the complete caller comparisons separately establish downstream behavior.

The tensor plan covers all 1,406 tensors in the observed model. Separate device
boundary checks exercise five tensor views, compare their first and last bytes,
and release each mapping and pipeline. The full proof process instead owns one
whole-file mapping with its individual tensor views for that process lifetime;
the separate-map release observation is not a per-view reclamation claim for
the full proof.

`observe/dsv4-proof-retention-run.bml` accepts four NUL-terminated fields:
`DPA1`, source directory, new archive path and `END`, with an optional final LF.
The source must be quiescent. Form supervises the OS archive operation,
retains complete stdout/stderr and exit status, creates the destination
exclusively, settles publication resources and verifies every archive byte.
Physical directory admission refuses an archive inside the source and a source
containing the capture directory, including aliases through directory symlinks.
These are cooperative path and lifetime contracts, not an atomic filesystem
snapshot against concurrent writers or parent replacement.

The three proof callers use `FORM_DS4_PROOF_ARCHIVE` to retain their compiled
inputs and internal native-reference streams. Relative paths bind to the
invocation directory. A retention failure preserves the work directory and
refuses a successful exit; an existing numerical failure retains its status.
The archive owner observes exact binary extraction, unusual filenames,
unchanged existing destinations, explicit refusal and resource settlement.

The north star is one Form-owned numerical graph with resident activations,
explicit concurrent leases and replaceable CPU/device programs. Comparison
captures the same input once, retains each selected version until completion,
and observes numerical behavior, resource footprint and execution cost together.
The comparison scripts use native Form emission and numerical references.
Their Swift GPU carriers and shell launchers remain visible host-side code,
including device compilation and numerical comparison orchestration.
