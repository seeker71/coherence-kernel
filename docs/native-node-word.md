# Native node identity

A node identity is generated directly as one unsigned 64-bit word. Package,
level, type and instance are views of that word. Their widths need no byte,
16-bit or 32-bit alignment. The Form authority is
[`native-node-word.bml`](../form/form-stdlib/bml/native-node-word.bml); its
[generator](../observe/native-node-word-generate.bml) emits the small native
[header](../runtime/fkwu-node-word.h).

## Current layout

| Format | Bit positions | Meaning |
| --- | --- | --- |
| Structured coordinate | 63 | Format bit is 1 |
| | 62–57 | Package: 6 bits, 0–63 |
| | 56–44 | Level: 13 bits, 0–8191 |
| | 43–32 | Type: 12 bits, 0–4095 |
| | 31–0 | Instance: 32 bits, 0–4294967295 |
| Integer coordinate | 63 | Format bit is 0 |
| | 62–0 | Signed 63-bit instance, −2^62 through 2^62−1; package, level and type are implicitly 1 |

The constructor uses integer format whenever package, level and type are all
1. Every other admitted coordinate uses structured format. Each coordinate has
one generated word; extraction uses masks and shifts. Integer payloads remain
exact across the tagged integer range. Cell kind remains separate: a trivial
integer cell and an explicit identity descriptor retain their distinct equality
semantics even when their coordinate views agree.

The selected structured widths admit current operator and lexicon coordinates,
including package 32, level 7000 and type 2026. They define an admission domain;
arbitrary four-coordinate values cannot all fit into a single finite word.
The constructor refuses an out-of-domain coordinate before claiming its shared
intern slot. Ordinary repeated identities reuse the existing cell.

## Storage, readers and transport

The node identity column is 8 bytes per cell. Ten logical column words account
for 80 bytes per cell. `kernel_stat(63)` reports identity width;
`kernel_stat(61)` reports logical occupied column bytes. Neither measurement
claims physical residency or achieved bandwidth.

The shared field has layout version 2 and names `/fg-field2-<letter>`.
Mapped readers validate the field version and the target's shared-field backing
before reading 8-byte identities. Per-process store targets are refused by
that shared-field reader. Closing a reader invalidates its field access.
The live-page reader checks its mapped extent before reading the requested
words. Other layout generations remain separate and are not reset or migrated
by admission of this generation.

Runtime cell handles still use the existing tagged value ABI. External
FORMBIN2, coordinate transport profiles and value crossings retain their own
encodings. Transport tuples are checked against the native layout when they
are instantiated as native identities. A transport encoding's width does not
determine the resident identity's width.

The shared field still reserves capacity for 2^26 cells and has no live
reclamation. At that capacity the identity column spans 512 MiB, and the ten
logical node columns span 5 GiB. These are capacity extents, not measured RAM
usage. Identity space and allocated population are independent.

## Executable observation and direction

The [source-bound executions](evidence/fkwu/native-node-word.json) retain real
child exits, complete outputs and source hashes. They cover extrema, field
separation, signed integers, kind-sensitive equality, repeated construction,
mapped projections, released-reader refusal, per-process storage, interning,
serialization, operator/lexicon use and Glass accounting. Ten settled children
exercise constructor refusals. Their global population readings remain
observations; concurrent allocation is not attributed to an individual child.

The [verification door](../observe/native-node-word-verify.bml) compares the
held header with the exact Form-generated bytes. The CLI builder runs that
door, includes authority and header in source identity, and copies the header
into its sealed build snapshot. Freshness includes header age and observed
8-byte identity width. The generated native constructor and readers remain a
temporary bootstrap carrier for Form-owned layout meaning.

The [north star](fkwu-form-native-north-star.md) keeps identity as one native
word while Form owns layout admission, specialization and version transitions.
Allocation grows or reclaims from actual available resources and named live
owners. A new layout must preserve an explicit admitted domain, reader
compatibility and outstanding ownership before publication. The current
generated-header bootstrap still requires compilation when its native layout
changes; runtime module replacement must take over that boundary before layout
evolution can happen without rebuilding the seed.
