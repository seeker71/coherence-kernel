# fkwu C bootstrap inspection

Witness date: 2026-09-10

Scope: `runtime/fkwu-uni.c`, `runtime/fkwu-optable.h`, and `form/native/metal/fk-metal-carrier.m`.

This inspection treats the C runtime as a temporary bootstrap carrier and shrink target. It supplies a complete lexical index of function definitions, globals and local statics, reconciles that index with the active Clang AST, and records semantic repairs with executable witnesses. Source-region labels and generated migration suggestions are navigation aids; they are not independent behavioral proofs for every symbol.

The neutral task framing used for this pass is:

> C bootstrap runtime architecture audit and repair pass for Form-native host integration.

That phrase is intentional. This is runtime ownership, resource lifetime, platform ABI, and performance work.

## Source-region map

The JSON locates every indexed symbol within 34 regions, anchored to named definitions. These cover values and intern pools; parsing, compilation and images; collection; host ABI and dispatch; CPU specialization; Metal; media; files; sockets and protocols; mapped stores; observation; and startup. Regions describe source organization. A declaration next to a region boundary still needs its own ownership reading; the declaration and references are retained for that purpose.

The outline contains 649 function definitions and 395 file-scope global declarations, including repeated declarations and conditional branches. The audit also includes 58 local-static declaration units. Distinct names and active-platform counts are given above so those different populations remain visible.

The separate Objective-C carrier inventory contains 33 function definitions and 40 file-scope global declarations, with zero unresolved lexical units. Its remaining process state owns device/queue admission, buffer and pipeline tables, open/submitted/shelved work, deadlines and counters. Form owns the new program descriptors, cache identity, thought recall and domain-specific policy selection. Moving those carrier globals into independently destroyable contexts remains necessary for full multi-context isolation.

| Form-generated Metal programs lacked an explicit compiled archive and live comparison witness. | Form owns in-RAM admission, exact version identity, optional binary-archive capture/reuse, and program selection. | Metal JIT live `4095`; archive capture/reuse `63`/`63`; refusal `127`. |
| Program selection lacked a direct connection to witnessed policy freshness and micro-thought recall. | A Form policy carries its domain, actual GPU-result witness, program version and epoch. A failed re-witness removes its eligibility; thought recall verifies source and entry. | `metal-jit-choice-band.fk` returns `2047` over real GPU programs. |
| Bootstrap regeneration could choose another compiler and source lists named a removed cell. | Both regeneration doors use native fkwu; source lists carry `form-cli-heedmark.bml`. Native emission normalizes table line endings before embedding C. | Native table canary answers `pong`; final publication is checked independently. |
| Full source-native table compilation exhausted the host stack. | Balanced Form literal and serialization traversals preserve exact bytes without raising the C stack wall. | `native-table-depth-band.fk` returns `127`; full CLI compilation produces 5311 functions and answers `pong`. |
| The Form reference walker lacked lexical frame and shared run-memory semantics. | Calls carry explicit argument/slot/memory context; recursive calls preserve caller slots, and runs own separate memory. | Frame `63`, string-lowering `63`, indirect-call `31`, kernel `31`. |
| Closure capture values could be lost when melted/shelved values were collected. | Added root marking/copying for closure captures in the melt path. | `form/form-stdlib/tests/closure-capture-melt-band.fk` returns `31`. |
| Frame reading used a fixed 1 MB process-global buffer. | Replaced the fixed buffer with an owned dynamic loader, validated BMP dimensions and row sizes, and released memory after use. | `form/form-stdlib/tests/frame-read-dynamic-band.fk` returns `127`; AddressSanitizer run returns `127`. |
| Frame interpretation lived only in C. | Added `form/form-stdlib/bml/frame-luma.bml` as a Form-native BMP luma witness for the same result shape. | `form/form-stdlib/tests/frame-luma-band.fk` returns `127`. |

These repairs remove hard limits, repair ownership, and create Form-native witnesses. The seed nevertheless grows by 301 lines in this movement; the receipt names the replacement and caller-migration obligations before that temporary code can be retired. A smaller eventual carrier is the target, not a reduction already achieved by this patch.

Add create/destroy context bands. |
| Tagged value ABI | `Node` is still a C layout and many helpers assume process-local storage. | Define a small versioned value ABI in Form, then make C translate only at the boundary. Add layout hash and overflow bands. |

## Function-by-function and global-by-global reading rule

The generated JSON is the per-symbol index for this source snapshot. Function records carry source position, signature, source-region family, call-shaped tokens, references matching global names, numeric tokens and a migration suggestion. Global and local-static records carry declarations and owner functions where applicable. Call-shaped tokens can be macros or indirect calls; matched names can be shadowed. Region boundaries are resolved from named definitions each run and missing/reordered boundaries prevent publication.

The review rule is:

1. If a symbol touches a host ABI directly, keep it in the carrier until a narrower carrier call replaces it.
2. If a symbol expresses policy, move it toward Form.
3. If a symbol owns mutable state, assign it to an explicit context, module, task, or resource.
4. If a symbol moves bulk data across the membrane, convert the crossing to handles/spans/fences.
5. If a symbol has no witness, add a band before leaning on it.

This turns the audit from a list into a migration plan. Each symbol either has a reason to remain in C for now or a named path home.

## Why the repairs matter

The closure repair makes captured values survive the same way visible stack values survive. That is semantic ownership.

The frame repair changes a fixed hidden process buffer into owned memory with validation and a Form-native decoder witness. That is data ownership and a smaller membrane.

The Metal repair changes fixed tables and ambiguous timeout state into visible capacity, explicit outstanding work, and safe release behavior. That is device ownership.

The Windows prototype repair removes accidental host assumptions so the next failure is the real carrier split. That is platform ownership.

Together these move the C seed in the intended direction: less hidden state, fewer fixed limits, clearer host boundaries, and more behavior returning to Form.
