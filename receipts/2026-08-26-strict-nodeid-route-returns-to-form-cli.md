## Movement

`form-cli-nodeid-knowledge-resident.fk` now performs the strict route in the
already-resident Form source image.  It does not map concepts to functions or
operations.  The mapping is the persisted body itself:

```
SHA256(concept) -> one bounded route file -> one bounded PSCI source record
                -> one current repository source snapshot
```

Admission checks the route-key hash, permitted family/root pair, path
containment, source and entry content keys, nonnegative held size, bounded key
cardinality, query and canonical unique-key membership, current byte count,
and current SHA-256.  Every route file in the exact bucket is inspected before
selection, so duplicate valid routes are `ambiguous` while a missing or invalid
reference is refused rather than hidden behind the first readable filename.
The source is captured once for identity and answer construction, then
streaming-rehashed before return.  Disappearance after the registry hit is
`stale`.

The request walks the real immutable BMF raw-byte cursor with bounded fuel.
Malformed NodeID coordinates are `failure`; an absent valid concept is exact
`nothing`; over-window read is `timeout`; 0 and 1 remain present values.  The
successful trace retains `choice,cut,release`; failure retains
`choice,failure,cut,undo,refine,release`.

The returned evidence enters the existing content-addressed thought image.
That result is deliberately named `resident-thought-self-consistency`: the
image compares the producer's correlated evidence after production; it does
not yet produce the route result and is not claimed as producer equivalence.
One content-redacted framebuffer event is retained for each query.  The event
keeps only source/absence NodeID and origin; query and answer text do not enter
the diagnostic stream.  This movement observes the event but does not claim a
bidirectional control exchange.

The active REPL now calls `fcnkr-stage` and `fcnkr-query` directly.  Its
`host-exec`/`fcnkc` query arm is absent.  A live piped session observed:
