## Carried

- **general-mutable-local-source-lowering**, `form/form-stdlib/tests/bml-hati-native-mutable-locals-proof.fk`,
  34 of 34 on fkwu. `int x = 1;` declares, `x = expr;` rebinds (inside a nested block too), and what
  follows the block reads the rebinding. Declare and assign ride `BML-AST-CALL` as `__bnml_declare` and
  `__bnml_assign`, the home `this.f = N` already has in `__hati_field_set`. `bml-local-env-after-node`
  binds them with two readings: the value node and its env for the BMA lane's substitution, a kind and
  a frame slot key for the Hati lane. A block keeps its declarations and lets an assignment to an
  outer name ride out. On Hati each body that declares or assigns opens one frame per call: slot 1
  (tag 109) holds a recipe record (tag 64) whose blueprint row is `BML-MUTABLE-LOCAL-FRAME`, the
  carrier's own blueprint; declare and assign are record sets (98), reads are record gets (97). A
  shadowing declaration gets its own slot (name plus env depth). An unbound target, a const target and
  a method target are named before any table exists.
- **general-arrays**, `form/form-stdlib/tests/bml-hati-native-arrays-proof.fk`, 28 of 28. `#(a, b)` takes
  any expression (names, sums, nested literals); `a[i]` indexes a literal, a const, a mutable local or
  another index, and lowers to nth (tag 23) over the cons list. The BMA lane gained `array` and `index`
  ops for value positions (return, element, index target); a bare array statement still pushes its
  items, the meaning `bml-action-runtime-band` holds. `array-int` joined the executable rules. An index
  the compiler already sees out of range, or into a scalar, is named before emission.
- **source-restore-spelling**, `form/form-stdlib/tests/bml-hati-native-restore-proof.fk`, 17 of 17.
  `restore-simple` has its rule, emitter, inverse, executable row, native row and recipe row; the node
  round-trips; on the BMA lane `mark; ... restore;` returns the stack to the mark (value 2 where the
  unrestored run gives 7, snapshots 0).

## Still open, with the reason

- **Hati save/restore/discard.** Hati still names restore before emission. It has no state snapshot
  yet, so save and restore are both named there; lifting restore alone would lower it to a silent zero,
  and a frame snapshot would read differently from the BMA lane's stack snapshot.
- Assignment inside choose/try/while branches is not carried across the branch; the carrier's next
  code point names it. Element assignment `a[i] = v` and calls inside the general expression grammar
  are not read yet; calls belong to the lane working on names and calls.
- `dialect-categories.fk` is still generated by a Python script. No category was needed here, so that
  generator did not come home in this movement.

## Closing

Most surprising: the reference lane reads a local by substitution and the native lane reads it from a
frame, so one binding has to carry both. `const int y = x + 1;` showed why: substituted at its use,
after `x = 10`, the native lane would have answered 11 where the program means 2, under a green
table. A const becomes a frame slot exactly when it reads something that can change.

Discomfort to gold: the family seemed to want an ASSIGN category, the registry holds no BML-AST row
to take, and the generator is a script we do not run. Staying with that instead of minting showed
the file's own `this.f = N` lowering: a statement already spelled as a reserved call. No coordinate
minted, no generated file touched.

Frontier word: **twinread** (0 hits in the tree). When one binding is read by substitution on the
reference lane and through a frame slot on the native lane, what keeps the two readings the same
value once state can change under them?
