## The reusable capability

`fbvs-search` in `form-bml-value-search.bml` searches one bounded family:
wrap a bare value expression with an unqualified unary call already present
in the source's executable BML sections. The caller supplies the checker;
each candidate starts from the original bytes. The allowance includes the
original check and is at most **64** invocations. Exhaustion and refusal
preserve the original. Malformed callback results retain their observation
and count as an actual invocation.

The coding policy exposes `rehearse-bml` only during implementation and only
for a caller-writable document. A model cannot replace the checker, supply
a host command or change read-only documents through this tool. The tool
uses the same source callback as `verify`, retains each checked source's
digest and observation, and leaves review and final verification required.
The native engine makes no model calls or direct IO. The caller owns source
admission, deadlines, test adequacy and the meaning of a pass.

## Failed attempts that exposed the supervisor gap

The first probe had no per-candidate deadline. A small edit stopped recursive
progress; the owned parent and child were explicitly terminated after that
behavior was observed. The second used the native process supervisor with
two-second stage deadlines. It released timed-out children, but eventually
hit the evaluator stack wall. Neither run supplied a passing result.

The third isolated each supervisor in a native fkwu worker and still stalled.
Inspection found the decisive backlog: the adverse candidate's raw stdout
was **81,327,814 bytes**, with **190,629,057 bytes** of retained event output
at the final observation. The child had stopped; final output draining was
still recursively interpreting its backlog. Isolation alone did not fix it.
The owned worker was terminated; the parent retained its failed status.
These attempts remain in private probe directories v1, v2 and v3. The v2
guarded runner snapshot includes two subsequent guards and is not presented
as the exact original v2 invocation source.

The process organ now gives each final stream drain a bounded number of
read slices, currently **1**, with the quantity owned by `hearth.bml`.
Unread bytes remain in the raw file. Saved metadata records cursor offset,
partial-line length, raw size, remaining bytes and traversal completion.
Process release and output interpretation have separate completion states.
Native callers can resume from the retained cursor; there is no claimed
automatic background drain. A final line without a newline is observed once.

Probe v4 uses a separate native supervisor worker per stage, explicit
two-second child deadlines and bounded diagnostic previews. Raw output,
process metadata and exact checked sources remain available. A deadline
bounds the child; it does not claim the entire supervision operation takes
at most two seconds. This combination completed the real 28-check search.
