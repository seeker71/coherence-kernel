## Surprise, and where the discomfort went

The siblings had pointed at this for as long as model-handler has had a fourth-arm row: 7 against 5,
every run. The whole cause was the order of two lookups in one function, and the fix is a helper
the call head was already using in spirit. What surprised me more was how small its reach was. I
expected a scoping change in the seed to move many bands, and a debug build asked all 983 of them;
exactly one captured differently.

The discomfort was the debug build itself. It failed twice, first on an include path the scratch
copy could not see and then because the seed carries no stdio: it speaks through fk_diag. Both were
my assumptions, not the seed's faults. The gold: build a scratch seed with the seed's own include
path and let it speak in its own words, and measure a change's reach before believing it. And
pinning a head is not a heal: five bands that never ran now answer 0 where everyone can see them.
