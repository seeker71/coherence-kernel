## Repair embodied in the ordinary native path

`form-cli-boolean-report.bml` normalizes exact lowercase string literals
`yes`, `no`, `true` and `false` only for root fields whose original caller
check requires a JSON boolean. It derives the output type from the assertion
and the truth value from the submitted literal. Opposite expected truth values
produce the same proposed report; the original checker still rejects a
contrary decision. Other fields retain their values. Numeric 0/1, null,
missing fields, uncertain wording, duplicate root keys and unsupported query
shapes are declined.

The ordinary JSON review executor installs this callback through
`fcaq-live-checker`; embedding callers keep the existing four-element
`fcaq-checker` contract. Accepted changes retain native repair attribution
and pass through the full original checks. Type-mismatch feedback additionally
names expected and actual JSON types, without disclosing expected values.

Replaying the actual first failed dialogue submission completed in 16–17 ms,
one policy turn and two check calls, with no model or provider call. The
original answer and next-action strings and all source documents were
unchanged. The updated report passed its original assertions. This measures
retained-submission replay, not a replacement end-to-end session. Its poor
prose and the fixture flaw remain visible; type repair fixes neither.
