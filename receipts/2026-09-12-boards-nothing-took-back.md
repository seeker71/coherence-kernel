## Carried

- **A hot exit takes back the boards of writers that have ended** (e79a2c0a). fk_heat_write answers
  which boards it placed. When a process places one at exit, fk_heat_bury_ended walks its working
  directory and unlinks the boards of that kind, and their `.tmp` staging files, whose pid
  fk_pid_gone reads as ended or a zombie. A board whose pid still answers, a process of this user or
  another, is never touched: the glass reads its resident's board while it runs, and the per-pid
  name exists so that a short run cannot erase it. Each kind is taken back only by an exit that
  placed one of its own, so the last hot writer of each kind still speaks after it ends. The comment
  above the writer, which said one file per working directory, now says what is.

## Surprise, and where the discomfort went

The first witness took nothing back, and that was the rule working. The spin I wrote to be hot
placed no board, so its exit swept nothing; only the corpus band, whose hdc-row the morning's
boards already named, placed one and swept. Who takes boards back is decided by the writer's own
threshold: a process sweeps only when it is itself a board-writer of that kind.

The discomfort was unlinking files another process wrote. The per-pid name exists so that one run
cannot erase another's work, and a sweep is exactly that kind of erasing. What turned it was finding
the question already asked in the runtime: fk_pid_gone, which reads a zombie as gone since the ear's
live lane stayed alive as a corpse on 11 September. The burial asks the roster's question, and the
witness planted a living board for it to keep, and it kept it.

Frontier word, row 1472: **boardsilt**, the boards a catching signal leaves when nothing takes them
back, one per ended writer, settling in a directory until they outnumber everything else in it.
