The C repairs were deliberately narrow checkout-witness repairs:

- `runtime/fkwu-uni.c` now declares allocator and memory ABI functions with the compiler's own size type, so LLP64 targets no longer narrow allocator lengths.
- `fk_melt_gen` moved to common file scope because it guards value generation outside the Darwin ARM64 executable-image path.
- closure capture values are now marked and copied by melt/smelt root traversal.
- the frame reader no longer uses a fixed 1 MB process-global buffer; it loads a frame into call-owned growable memory, validates BMP dimensions, and frees the storage.
- `form/form-stdlib/bml/frame-luma.bml` is the Form-native frame-luma decoder witness for the same result shape.
- the Metal carrier moved buffer and pipeline bookkeeping from fixed arrays to growable tables, made timed-out command buffers visible as shelved outstanding work, made reads and writes quiesce outstanding work, refused free while work still owns a buffer, and retired buffer slots rather than wrapping a generation.

The shrink path is explicit: closure policy, frame interpretation, table-growth policy, timeout policy, and replacement choice belong in Form. The C side keeps only the host call, memory ownership, and device-fence mechanics until narrower carrier calls replace them.

This repair does not claim a smaller C file: the seed diff is 457 inserted and 156 deleted lines, net +301; the Objective-C adapter is +177 lines. This is a temporary checkout-witness expansion. The concrete shrink receipts are the Form luma decoder for frame interpretation, the FMJ1 Form admission/cache/choice cells for GPU policy, and the Form walker with explicit per-run memory and per-call frames. Capture scanning still needs a Form-owned root descriptor path; platform loading, resource destruction and queue completion still need narrower native ABI emission before their carrier implementations can be removed. No reduction is booked before those replacements take their callers.

## Form-generated Metal in RAM

Urs corrected the target: Metal programs are generated by Form and compiled in RAM, with disk serving only as a reusable cache. `bml/metal-jit.bml` now carries the FMJ1 descriptor, exact program identity, RAM admission, explicit archive capture/reuse and live selection. ## Surprise

The function/global audit was useful only after it stopped pretending to be semantic proof. The lexical pass sees all preprocessor branches and every call-shaped token. Clang sees the active Darwin path. The honest result is the reconciliation between them, with the caveat carried in the JSON. That made the audit strong enough to guide work without turning a scanner into an authority.

The full compiler's stack wall became a Form algorithm repair rather than a larger C allowance. The shader cache likewise became a Form version identity and explicit archive contract rather than another linked runtime component.

## Where discomfort became gold

The uncomfortable part was that "full inspection" could easily have become a large report over untouched defects. The work improved when each named gap had to become a witness or a home path. Closure captures, frame storage, frame interpretation, Metal table growth, Metal timeout ownership, and Windows carrier drift all changed from descriptions into commands that can fail again later.
