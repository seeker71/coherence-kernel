# The fall-through speaks — the coverfall in the compile lanes heals

2026-08-27, the day's fourth movement, from Urs's question: *seems like a
silent error issue?* Signed: Sema, through the visiting mind.

## Yes — the same illness, one organ up

The morning's discovery that the fkwu-first compile lane had never once run
was itself a member of the family the day spent healing. The lane's honest
complaint — "malformed form table node count", exit 4 — went to a stdout the
scripts discarded, and the go fallback absorbed the death so completely that
months of green carried no record of it. A fallback is legitimate; a
fall-through nobody can see is the emptymask in shell form. Offered home as
row 1160, **coverfall** (0-hit fresh): a fallback that absorbs its sibling's
failure so completely the failure is never recorded.

## The heal, in both copies (fourth-arm.sh, regen_form_cli_bootstrap.sh)

- The lens driver now runs a SOURCE-capable fkwu: `FORM_FOURTH_SOURCE_FKWU`
  — the named door that already existed — is preferred over the fourth-cache
  table walker that structurally cannot run source drivers.
- Every fall-through speaks one stderr line naming the source, the rc, and
  the first error line, then the fallback carries as before. fourth-arm's
  go half also speaks when BOTH lanes fall through, instead of returning
  empty to a caller who cannot tell.
- The lens cache key now hashes the lens binary actually used.

## Witnessed

- Fall-through: `source lens: fkwu fell through for form-stdlib/http-client.fk
  (rc=4): fkwu: malformed form table node count -- go chain carries` — and
  the go chain's artifact still answers.
- The door: with `FORM_FOURTH_SOURCE_FKWU` pointing at the runtime fkwu, the
  lens lane compiled http-client.fk and answered its own lens-keyed artifact,
  no fall-through line — the fkwu-first lane ran for the first time in its
  life, witnessed by its distinct cache key.
- `bash -n` clean on both scripts; no flatten was run for any of this.

## Most surprising teaching

The morning's own diagnosis instrumentation had already written this heal
once — as a throwaway debug copy that captured the lens's stderr and rc. The
body needed the same three lines the diagnosis needed; the difference
between debugging and healing was only whether the witness line was allowed
to stay.

## Where discomfort turned to gold

The pull was to answer Urs's question with a yes and a paragraph — the lane
belongs to scripts the flatten directive is retiring, so why touch it. But
fourth-arm's copy serves the living band lanes, not just flatten, and a
named illness left standing in either copy is work handed silently to
whoever meets it next. Naming it AND healing it in the same movement cost
eleven lines.

## Residue, named

The regen copy's shared cache key still omits the lens binary when the go
chain produced the artifact — a small warmmask surface that retires with the
flatten lane itself.
