# Form owns a bounded provider repair and its replay

Signed: Codex, 2026-09-16.

The retained native translation case still failed after a local repair. Form
now has an optional resource that carries that kind of unresolved read-only
report through a provider CLI, rechecks the answer and retains actual usage.
The native `code` loop remains local-only. No C seed or foreign runtime was added.

## The implemented resource

- Authority: `form/form-stdlib/bml/form-cli-response-resource.bml`.
- Door: `observe/form-cli-response-resource-run.bml`.
- Caller contract: `docs/form-response-resource.md`.

The caller supplies an evaluation review contract, actual retained local report
paths and permission for one provider process with a positive deadline. Form
checks the source and latest report before deciding whether the resource is
needed. Expected report-check values stay outside the provider prompt.

The existing native process organ supervises the CLI in an owned empty directory
outside the repository. The result names its provider origin. Acceptance requires
the unchanged source/report checks, observed usage, process completion and release.
Overall semantic quality remains unassessed by this contract.

An atomic claim binds the complete request and retained report bytes. Repeated
calls recheck the frozen answer and report zero new processes. Answer and usage
hashes must still match. The original usage belongs to one stable event and is
not added again on replay. An incomplete claim returns its evidence location
without silently starting another provider process.

The shared evidence writer now checks the write result, file presence and exact
bytes. Equality with an empty read alone cannot establish that an empty file
was successfully retained.

## Actual repair and replay

The local reports called an absent translation a rejection. Both original and
repaired local answers remain intact. A private native prototype handed that
failure to one provider process; the unchanged check then passed. It took
8,504 ms, with 16,780 input tokens, 10,624 cached input tokens and 27 output tokens.

The public entry point was then exercised independently:

| Observation | Value |
| --- | ---: |
| New provider processes | 1 |
| Source / report / usage / release checks | 1 / 1 / 1 / 1 |
| Process duration | 14,743 ms |
| Input tokens | 16,816 |
| Cached input tokens, included above | 10,624 |
| Output tokens | 27 |
| Input plus output | 16,843 |
| Replay: new provider processes | 0 |
| Replay: original assertions and release | passed |

The provider corrected the rejection field while preserving the concept,
requested language and absent translation. This is a provider-assisted repair,
not a newly native semantic capability. The original probe froze its program
but not the expanded source inputs; reconstruction from that program and the
current committed axioms is explicitly recorded. The public resource freezes
its actual request and reports. This is not a matched whole-session comparison.

Separate, explicitly labelled state fixtures exercised a claim before its
request appeared, a request without a terminal process record and a partially
written process record. All returned their pending state with zero new provider
processes. A changed-source negative control also withheld the provider.
These fixtures are not provider execution evidence.

## Native thinking: stronger detail, substantial cost

The corrected private thinking-session harness let the model's `verify` request
reach the native controller and continue. The exact eight-document request
completed in 940,826 ms: two replies, one tool call, no repairs, 2,644 generated
IDs, 169 injected IDs, unchanged report checks passed and resources released.
Its initial thinking reply used 1,638 IDs. No provider was called by this run.

My reading: the answer now uses the exact short anchor and missing German row
and explains their roles more fully. It still conflates seeded relations with
numeric IDs. The earlier no-thinking answer took 383,463 ms and 457 generated
IDs. This supports further work on an optional reasoning mode; it does not
justify changing the default or claiming parity. The working harness and exact
answer remain private evidence, and production chat templates are unchanged.

## Validation, learning and cost

The resource band and response-session band each returned 1; the hearth band
returned 32767. Preflight reported zero errors, warnings and unresolved names.
The resource checks cover permission, read-only evaluation scope, source failures,
incorrect reports, absent usage, lifecycle, byte integrity, missing empty writes
and exclusion of expected report values from the provider prompt. The live
resource and replay establish the separate process behavior described above.

Initial compile attempts caught misspelled `nsm_s` / `nsm_n`, a missing
`nss-reference` prelude in the private prototype, and an unavailable
`str_last_index` in the first public draft. These were repaired before their
live provider calls; the failed compile logs remain retained.

The counsel panel showed **0 orphans** and **11 of 12 lanes unobserved** because
no resident hearth stands. The source-header teaching completed local learning
round 12, with four promotions and serving generation 5. The new verified
resource-boundary teaching was retained separately; assessment answers were
excluded. Its worker subsequently completed round 13, with promotions still four
and serving generation still five. This learner is Llama 3B, not a Qwen weight
update.

Coordinator turn `01a0a872-10e6-78e2-8d5d-431008584a65` used **81 provider calls**:
9,870,930 input tokens, including 9,517,312 cached and 353,618 uncached; 73,617
output tokens, including 47,375 reasoning tokens. The meter retained a separate
27,577-token attribution gap, giving its reported total of 9,972,124. These
coordinator figures and the individual CLI repairs have different scopes.
Whole-session savings, throughput and quality parity remain unproven.

The useful surprise was that opening native reasoning brought specific runtime
evidence into the answer. The harder observation was its cost, alongside a
separate semantic error that survived native feedback. The resulting capability
lets Form carry a bounded repair and verify its return without hiding the source.
