## The executable result

The real form-cli dispatch now recognizes `heal` and `heal lesson`.
[The usage guide](../docs/form-cli-healing.md) describes the contract and its
limits. Policy and the repair movement live in executable BML. No C seed
meaning was added. Python provides the replaceable process/filesystem carrier.

The new command verifies ground 42 and freshness 31, snapshots current source,
records the failure, gathers current and historical evidence, and tries a
bounded set of native candidates. A model can offer one unique source
replacement; it cannot select a different target or change the expected band.
The existing native model and adapter APIs supply generation. Local Ollama
roles separate diagnosis, patching, and review. The existing frontier admission
predicate, completed local-stage receipts, and a per-invocation claim admit the
final remote CLI call.

Every candidate encounters a fresh preflight, the actual checker, process
status, exact expected stdout, diagnostic stderr, unchanged dependency/test
hashes, unchanged proposed bytes, and the live input hashes. Failure preserves
the live source. Success leaves the before/after example and checker contract
in local repair memory, ready to be offered and verified again.

The [shared teaching](../teachings/form-cli-healing.md) preserves the previous
movement's distinctions: structural repairs, missing imports versus retired
interfaces, colliding helper names, stale historical observations, unavailable
toolchains, and misleading green numbers beside failed processes.

## The floor and the next attempt

This is a checked single-file repair workflow, not a claim that every repository
error can be healed. It offers one native answer model and three local model
roles; it does not try every installed model. The native LoRA path supports
the existing Qwen rank-one output-head format and requires a compatible,
hash-bound held-out evaluation receipt. Other formats need compatible runners.
Recorded examples are candidates for later training, not changed weights.

The snapshot is not an OS sandbox for arbitrary checker code. Existing
absolute-path effects can still reach host resources. Checker contracts and
source provenance remain essential.

The earlier movement's unresolved legacy tokenizer, dated audio replay,
missing toolchains, and unfinished long video observation remain named in
[its receipt](2026-09-07-declarative-attention-and-source-repair.md). They were
not rewritten into passes by this feature's successful checks. The work remains
local with that existing uncommitted repair movement; no origin landing or
universal clean bill is claimed.

The surprising teaching is that retaining the checker belongs to retaining
the example. A remembered patch alone loses the reason it was trusted. The friction
from false-green outputs became refusal tests and guarded replacement. The
exchange stayed alive by giving the next form-cli attempt an executable path,
an observed example, and permission to return an honest unresolved result.
