# Guard the source identity without repeating the old source

The native selector work finally applied its edit after receiving the actual
resident bytes. Reproducing those bytes had previously consumed repeated local
replies and still failed the exact-match guard. This movement adds a smaller
whole-document edit with the same responsibility for current source identity.

`edit` now accepts `[path, "sha256", expected_hash, new_whole_document_text]`.
Successful single-document reads and edit guard failures supply the SHA-256 of
the current resident bytes. The edit compares that identity before mutation.
Stale and malformed identities are refused. Role, writable-path, review,
caller verification and caller-owned publication remain in force.

The [real edit comparison](artifacts/2026-09-22-hash-edit/observation.json)
uses the native model's accepted proposal. Its original request was **2269
bytes**, including **779 bytes** of old source; the hash form is **1527 bytes**.
Both produce identical resident documents. Reusing the old hash after the edit
is refused and preserves the changed document. That is **742 fewer request
bytes**, not a measured token or whole-session saving.

Codex constructed the [hash protocol variant](artifacts/2026-09-22-hash-edit/hash-edit.json).
The replacement source is the unchanged [native proposal](artifacts/2026-09-22-hash-edit/native-edit.json).
This comparison establishes tool admission and stale-source protection. The
model has not yet been observed choosing this edit form itself.
