## The checker was wrong

The first workflow ended with `attention`, not completion. I had expected a
bare `1` from native `rg -F -c`; its documented implementation returns
`path:1`. Both requested phrases were present exactly once and the source
preservation check passed. The faulty expectation triggered large failure
feedback, followed by `coding-observation-context-capacity`.

The correction changes only the two count-output expectations. The actual
candidate passes; the unchanged source and a candidate with an unrelated
source change both fail. Original requests, replies, checks and failure remain
retained. The original workflow remains incomplete. This was a rented
coordinator's checker mistake, not a failed native edit.

## Reuse what the context already carries

That run also read a 12,189-byte source already supplied in its model context.
Returning the full source again consumed context and a long observation pass.
The controller now snapshots the exact documents supplied at each admission,
including resume. A successful single-file `read` can return a context-scoped
reference only after its actual output matches those bytes exactly. Changed
content, failures and missing snapshots retain full output. `cat` remains
available; source and report checks still consume the actual document bytes.

A native replay of the recorded read preserved the documents and one tool
call while reducing the observation from **13,370 to 623 bytes**. This isolates
the transport change; response quality remains unmeasured by that witness.
The live workflow replay also uses the corrected checker, so its eventual
outcome cannot isolate the contribution of context reuse alone.
