# 2026-08-24 — a retrieved concept becomes a mastery cell

Coverage was not the requested crossing. A source being indexable says that a

## What now exists

`form/form-stdlib/form-nodeid-mastery-cell-loop.fk` composes one immutable state
through:

```text
discover → choose → retrieve → attempt → execute/observe
                                      ↘ undo/refine → next attempt
                                      ↘ crystallize → dissolve? → release?
```

The state retains the public concept key, original source and entry NodeIDs,
attempt and request NodeIDs, execution and answer observation, explicit
surprise/failure signal, lifecycle trace, bounded timeout budget, optional
persistence identity, and the previous cell/continuation/channel/mesh
identities. A later cell can retain this lineage. Transport and mesh broadcast
remain literal `0`; identity carriage is not reported as a crossing.

A resident decoded stream can offer:

```text
<|form:mastery-thought|>concept=KEY;attempt=LABEL<|/form:mastery-thought|>
```

The existing immutable BMF raw-byte cursor consumes the frame under finite
fuel. There is no tokenizer pre-step, flattening, operations table, C growth,
or model execution in the mechanism.

Retrieval and answer execution are callbacks. The pure band supplies fixture
callbacks; the dormant proposed adapter maps the existing path-free
`form-nodeid-knowledge-query` result into retrieval evidence. The answer side
accepts only already-observed evidence. It refuses `model-executed=1` when the
local-Qwen observation NodeID is `nothing`. Provenance of a non-nothing supplied
observation remains the live boundary's responsibility.

Present verdict `0`, present verdict `1`, and `nothing` remain three distinct
states. A verdict `1` can crystallize; `0`, absence, timeout, surprise, or
failure remains available to undo/refine rather than being hidden in a score.
