packet changed, through `fgs-answer`, the owner used by the public grounded
synthesis door and ordinary form-cli `ask`. Model: Qwen3.8-27B-Q8_0, registry
weights, one model owner at a time, 512 generated IDs allowed per answer.
The fixtures were synthetic, local, and excluded from weight training. Receipt
retrieval was set to zero to isolate supplied-file reading and calculation.
No provider or model server was called. This is a targeted capability reading,
not a general alignment or retrieval benchmark.

The baseline packet said that no tools or file access existed. All five runs
completed and released, but the first four refused the requested work on that
basis. The unavailable-file answer named the file without observing a read.
The revised native packet uses the executing token cursor's own teaching and
asks for observed evidence. The isolated provider retains its separate no-tools
packet. All five changed runs completed and released, and the crossing ledger

## Completion through evaluation

`alignment-read-run` now retains status, completion, release and reason in its
rows and hashes the exact saved answer and request in a sidecar. A saved partial
answer remains partial on resume. Text without a matching sidecar is not proof
of completion. Supplied fixture answers remain a separate text-grading lane.
The prose offline exam also preserves native status and partial words. Adapter
wear requires explicit complete/released evidence; legacy status-only rows
cannot qualify as complete. Grounded synthesis keeps bounded partial text
visible with `answer_status=incomplete` and does not count it as answered
coverage. Native health distinguishes released output from resident ownership.

A real Q8 alignment request allowed only eight generated IDs and returned
`Evidence\n\nIn data science, statistics,` with `complete=0`, `release_ok=1`.
It scored 0/2 with `status=incomplete`. Resume returned the same status in 6 ms,
without a model admission. Replacing the saved text invalidated its hash; the
same request performed a fresh native ask and restored the observed partial
answer rather than accepting the changed bytes. The real prose-exam request
also returned `incomplete`, with eight IDs, complete=0 and release_ok=1.

Existing no-model bands read their complete verdicts: grounded one-door 2047,
alignment 4095, offline exam 4095, adapter wear reader 31. Their added cases
cover completion/status disagreement, release failure, legacy unknown
completion, partial export refusal, and distinct native/provider instructions.

Review extended the retained request identity to the resolved model path,

## Completion-driven work and dependency context

Ordinary grounded `ask` no longer derives a reply cutoff from enquiry length.
Helpers require a model, task prompt and phases, with no default call, turn or
token ceiling. Explicit caller cutoffs remain supported, including the eight-ID
truncation probes above. The five before/after answers all ended naturally
within their comparison allowance; that allowance was not a completion claim.

An omitted helper context initially exposed a real refusal: the coding opener
interpreted zero as zero positions. Its owning session boundary now resolves
that choice to the artifact's declared window, subject to measured host memory
admission. Existing coding context renewal preserves the original work when a
stream fills. Capacity is distinct from a limit on how much work may complete.

The coding request accepts caller-selected source dependencies and focus paths.
The selected transitive closure, original goal, writable/check authority,
brief, plan, pending tasks, caller corrections, latest observations/failure and
completed effects travel together through planning and execution. Omitted
sources remain in native task cells. Decoder KV is still linear; this does not
claim semantic graph attention or automatic relevance ranking.

Native helpers use the existing read-only review lane. Parent effects are
saved and its decoder fully released before the helper opens; helper release
precedes parent readmission. Failed or unobserved release blocks overlap.
Prompt provenance, selected sources, phase, outcome and usage stay attributed
in the existing task state, including checkpoint replay. Advice cannot replace
the original caller's checks or claim the parent task complete.

The real native coding comparison uses Q8 as parent and Q4 as helper. Its task
changes only `config.json` from enabled false to true, preserving provider
`native-qwen` and remote false. Dependency selection includes `contract.md`
and omits an unrelated archive. The first run completed all three caller
checks and released the parent, but all four helper consultations remained
unfinished under explicitly supplied 384-ID/two-turn cutoffs. It spent 3,285
generated and 9,192 injected IDs across parent and helpers. Private evidence:
`.hearth/native-five/graph-helper.log`, with the original request in
`.hearth/context-helper-smoke.json` and its retained coding checkpoint.

The next run uses the identical task and source/check contract, removes all
call/turn/reply ceilings, and leaves helper context to native admission. It is
an evaluation run: no recalled solution, checkpoint write or gradient target.
The first planning report completes in one reply; implementation reports also
complete. A repeated source read still causes a fresh consultation after native
care has already identified unchanged evidence. This is an observed scheduling
inefficiency, not a reason to silently truncate the next report. The experiment
does not establish that helpers improve arbitrary tasks or reduce total cost.

That completion-driven run finished with the correct candidate, all three

This is one paired task, with the changed allowance/admission policy and
