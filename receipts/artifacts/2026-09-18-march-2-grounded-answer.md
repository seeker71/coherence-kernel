## What the seed field actually defines here

Of the nine terms, only four have an authored entry in `cognition/form-neutral-word-field.fk`: **vitality**, **trust**, **sovereignty**, **resonance** — plus **rented** in the word-field dictionary. **Quality, volume, frequency, traceability, and membrane** returned `nothing: no exact entry` — so for those five, what follows is structural reasoning from the two call shapes and the receipts, not a resource-backed definition. I'll flag that split as I go.

## Direct form-cli query vs guided form-cli session

**Vitality** — seed 2: *"how a whole still do and be more"* → flow. A direct query is one call; whatever form-cli does internally (its own Claude/Codex calls) stays inside one whole, in flow, uninterrupted. A guided session breaks that whole into fragments — the agent stops the flow to interpret, then re-enters. By this definition, the direct query has higher vitality; the guided session trades continuous flow for control.

**Trust** — seed 7: *"when what other say and do are the same again"* → sovereignty. The direct query's raw output *is* what form-cli did — nothing between the saying and the doing. The guided session inserts the agent's interpretation between each call; the agent's read of "what happened" can drift from what form-cli actually did, so trust has to be re-earned at each hop rather than held once.

**Sovereignty** — seed 8: *"when a self know what it want and do and not make other less"* → vitality. Also `receipts/2026-09-04-sovereignty-as-gift.md`: proven when a self doesn't need the external world to survive. In the direct query, form-cli is sovereign — it decides its own internal call plan and executes it unsteered. In the guided session, sovereignty moves to the agent, which is now choosing what happens next; form-cli's own sovereignty is reduced turn to turn. Not a net gain or loss — a relocation.

**Resonance** — seed 12: *"when 1 thing do and other thing do the same"* → harmony. Direct query: agent and form-cli move as one act — call, raw output, done — resonance is given, not built. Guided session: resonance has to be worked toward across turns, since each interpretation is a chance to align or to diverge before harmony is reached.

**Rented (tokens)** — dictionary sense 5157: *"from other place and not here."* `receipts/2026-08-31-bml-rented-turn-meter-delta.md` shows the danger directly: summing every textual output-tokens field (including cumulative totals) produced an impossible `25,826,352,066` and was refused as evidence. `receipts/2026-09-01-rented-session-local-form-ratio.md` shows the opposite case — local Form-cli reaching zero remote tokens. Applied here: a direct query has one agent-level crossing, so rented tokens are just form-cli's own internal spend, counted once. A guided session has N agent-level crossings, each potentially carrying its own internal spend — the same double-counting risk the 08-31 receipt names applies unless each call's rented cost is measured as a caller-bound delta rather than summed cumulative fields.

**Membrane** — no seed entry, but this repo has direct receipts on it. `receipts/2026-09-03-zg-enters-form-cli-without-membrane.md` treats crossing into a non-Form implementation (shell, host filesystem) as the thing to avoid; `receipts/2026-09-04-cell-channel-membrane-on-glass.md` and `receipts/2026-08-26-resident-cursor-and-membrane-homecoming.md` treat a membrane as something that should "speak" when used, i.e. be accounted for, not silent. A direct query is one external membrane crossing (agent→form-cli), with form-cli's own internal crossings to Claude/Codex nested inside but not agent-visible. A guided session is N external crossings, each with its own nested internal crossings, plus the interpretation step itself is a return-and-re-cross — this is exactly the loop `AGENTS.md` item 8b names: observation out, a correlated control decision back in, re-observation. A direct query is a single observation with no return decision; a guided session is that live-diagnostics loop running explicitly.

**Traceability** — no seed entry. Structurally: a direct query's internal trace lives entirely inside form-cli and isn't visible to the agent, even though the problem statement says all tokens are measured there. A guided session produces an agent-visible trace at every hop — each call and its output is a separate, inspectable record. So external traceability is higher in the guided session, but this is inference from call shape, not a defined or measured term in these resources.

## What this does not establish

**Quality, volume, and frequency** have no authored entry at all. I can say a guided session produces more raw calls (higher call frequency, higher raw output volume before combination) and a direct query produces one raw output — but nothing in these resources defines "quality," so no claim that either produces a *better* answer is supported here. That would need a separate, named quality metric, which doesn't exist in this material.
