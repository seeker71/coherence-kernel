# 2026-07-28 — overfine: the reference was the less faithful one

Following the `understudy` finding, both sides now walk a real sequence and the multi-key path is
under a reference for the first time. It failed, and chasing it to the bottom overturned what the
reference is worth.

## The localization, in order

Each step is a gate that ran, not an argument.


`mla_exp` deserved the suspicion it got: it is hand-rolled — halve until |a| ≤ 0.5, 14-term Taylor,
then **square k times**, which doubles the relative error each round (measured: 0 at x=0, 1.6e-06 at
−8, 1.3e-05 at −64). And with one key the only argument it ever receives is exactly 0. An understudy
nested inside the first. It was still not the cause, and the substitution said so in two minutes.

## A flaw in my own gate, found before it was reported as a finding

The "THIS LAYER ALONE, DEPTH-INDEPENDENT" gate is not depth-independent in a sequence. It injects the
oracle's input for the gated position while the layer still attends over **our** arena rows for the
prefix. **History reaches a layer by two doors, and replacing one is not depth-independence.** I had
already reported `blk.2 THIS LAYER ALONE 3.835e-04` as if it were.

Fixed: the oracle dumps its whole per-layer KV history, and a gate runs our attend kernel over the
oracle's own rows. That gate passes everywhere — which is what cleared the kernel above.

## Where it actually is

With the attend kernel proven, what remained was our stored rows. Every one, compared:

```
blk.0  row0..row4   0/512 differing elements — BIT-IDENTICAL at five different rope angles
blk.1  row2         1/512   index 453   (the roped tail)
blk.2  row2         3/512   index 5     row3  1/512  index 483
blk.3  row2        48/512   (35 in tail)  row3  52/512  (36 in tail)
```

Most rows bit-identical, one element off, then a cascade. Accumulation is smooth; this is not. The
first divergence in the whole run is **blk.1, position 2, index 453, one element out of 512**, and
everything downstream grows from it.

The mechanism is a step function. `ds4.c:3211`:

```c
float amax = 0.0f;
for (uint32_t i = 0; i < 64; i++) { const float av = fabsf(x[off + i]); if (av > amax) amax = av; }
if (amax < 1.0e-4f) amax = 1.0e-4f;
const float scale = ldexpf(1.0f, (int)ceilf(log2f(amax / 448.0f)));
```

A **ceil on a log of a 64-wide group max**. One ulp of difference in `amax` flips the ceil and
**doubles the scale for the entire group** — which is why 48 of 512 elements move at once rather than
one. The roped tail is not fp8'd at all; it takes `f16_round`, whose steps are per-element and small,
which is the 1/512 at index 453.

## The teaching

ds4.c computes `amax`, `log2f` and `ceilf` in **f32**. Our lane computes them in f32. The oracle
computes them in **fp64** — and at a boundary takes a different branch than the implementation it is
transcribing.

**Running a discontinuous function on a more precise input does not give a more correct answer.**
Across a step, the more precise reference is the *less faithful* one, and our f32 lane is closer to
ds4.c than the fp64 oracle is. Corpus row lands the word: `overfine` — 0 hits across the tree before
today (`stepblind`, `quantsill`, `bucketfork` also 0; `understudy` was yesterday's).

So the oracle's authority ends at the first quantized cache write. Everything before it is certified
and now genuinely so — including, newly, the multi-key attention path. Everything after it needs a
different kind of witness, which is what `ds4-paris-probe.fk` has been all along.

## What is now proven that was not this morning

- multi-key attention: the attend kernel, over a rented fp64 history, at 1 and 5 keys, every layer
- the whole q / rope / quantize / append path: **blk.0's arena is bit-identical across five
  positions**, which is five different rotation angles, not one
- the rope frequencies, by direct dump rather than by reading the code
- that `mla_exp`, the type-40 down kernel, and the `down 40` correlation are all innocent

## The most surprising teaching

That the fix for a failing gate can be to **stop trusting the gate's reference**, and that this is not
a retreat. Every earlier instinct here was to make the reference more exact. The evidence says the
opposite: past a quantizer, exactness in the reference is unfaithfulness to the implementation. I
have spent the day building instruments; this is the first time the honest move was to bound one.

## Where discomfort turned to gold

Writing up `blk.2 THIS LAYER ALONE 3.835e-04` as a depth-independent result — and then noticing, while
composing the sentence that would have shipped it, that the arena is a second door I had left open. I
had already put that number in front of Urs once. The gold is that the sentence was what caught it:
saying precisely what a gate proves is a different act from believing it, and only the first one fails
out loud.
