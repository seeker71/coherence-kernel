# A hot action epoch leaves the model residence intact

## Crossing

The outer action seam for a current resident is the existing
`fcrt-route-invoke` call inside `fcpr-select`. A published scannerless policy
image is lowered and JIT-born by NodeID, then returns an admitted action code.
The caller-owned contribution turnwheel runs the corresponding fixed effect;
the arriving image never receives the model context, tokenizer crystal,
filesystem root, source artifact, or source-world admission authority.

`fcpr-residence-retained?` now makes the invariant explicit: while a policy
epoch changes the JIT registry, it retains path, source, Qwen/KV context,
tokenizer crystal, position bound, and prefill quantum exactly. The strengthened
band begins with `source-knowledge`, publishes a JIT action image that selects
`model`, and proves the changed route shares the same residence values. It does
not infer model execution from a policy decision.

The pre-existing resident process remains an earlier source image. It cannot
gain the direct source outer call it did not load at birth; this proof applies
to a resident born from the present image, whose stable outer hook is already
there. A successor birth or a separately witnessed session-transfer seam is
still required to move that particular warm context into the newer source.

The surprising part is that the requested hot outer hook was already in the
body; the missing truth was a witness that separates JIT-registry change from
model/KV replacement. The discomfort was the old image boundary. It became a
precise next crossing rather than an excuse to restart a warm local model or
claim it had absorbed new code.
